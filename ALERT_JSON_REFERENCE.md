# Alert JSON Reference - MGC Alert-Only System

## Complete Technical Reference for TradersPost Webhook Integration

This document provides detailed specifications for all JSON alert messages generated by the MGC Alert-Only indicator.

---

## Alert Types Overview

The system generates the following alert types:

| Alert Type | When Triggered | Purpose |
|------------|----------------|---------|
| Entry Long | Confluence >= 7, bullish | Open long position |
| Entry Short | Confluence >= 7, bearish | Open short position |
| TP1 Exit | Price hits TP1 | Exit 70% of position |
| TP2 Exit | Price hits TP2 | Exit 25% of position |
| TP3 Exit | Price hits TP3 | Exit final 5% |
| Stop Loss | Price hits stop | Emergency exit all |
| Stop Update | BE or trail triggered | Update stop price |
| Flatten | End of day (15:50 ET) | Close any open position |

---

## Entry Alert JSON

### Long Entry

```json
{
  "ticker": "MGC1!",
  "action": "buy",
  "orderType": "market",
  "quantity": 1,
  "stopLoss": {
    "type": "stop",
    "stopPrice": 2515.80
  },
  "takeProfit": {
    "type": "limit",
    "limitPrice": 2608.30
  },
  "sentiment": "bullish",
  "confluenceScore": 8
}
```

### Short Entry

```json
{
  "ticker": "MGC1!",
  "action": "sell",
  "orderType": "market",
  "quantity": 1,
  "stopLoss": {
    "type": "stop",
    "stopPrice": 2608.30
  },
  "takeProfit": {
    "type": "limit",
    "limitPrice": 2515.80
  },
  "sentiment": "bearish",
  "confluenceScore": 7
}
```

### Entry Field Descriptions

| Field | Type | Description |
|-------|------|-------------|
| `ticker` | string | TradingView symbol (MGC1!) |
| `action` | string | "buy" for long, "sell" for short |
| `orderType` | string | Always "market" for entries |
| `quantity` | integer | Number of contracts |
| `stopLoss.type` | string | Always "stop" |
| `stopLoss.stopPrice` | float | Initial stop loss price |
| `takeProfit.type` | string | Always "limit" |
| `takeProfit.limitPrice` | float | TP1 target price |
| `sentiment` | string | "bullish" or "bearish" |
| `confluenceScore` | integer | Score from 0-10 |

```json
{
```

```json
  "action": "sell",
  "orderType": "market",
```

### Breakeven Stop Hit

```json
{
  "ticker": "MGC1!",
  "action": "sell",
  "orderType": "market",
  "quantity": 0.3,
  "reason": "breakeven_stop"
}
```

### Trailing Stop Hit

```json
{
  "ticker": "MGC1!",
  "action": "sell",
  "orderType": "market",
  "quantity": 0.3,
  "reason": "trailing_stop"
}
```

### Stop Reason Values

| Reason | Description |
|--------|-------------|
| `initial_stop` | Original stop loss hit |
| `breakeven_stop` | Stop at breakeven hit |
| `trailing_stop` | Trailing stop hit |

## Price Calculation Formulas

### Stop Loss Prices

```
Long Entry Stop = Entry Price - (ATR × 1.2)
Short Entry Stop = Entry Price + (ATR × 1.2)

Breakeven Stop (Long) = Entry Price + (2 × tick size)
Breakeven Stop (Short) = Entry Price - (2 × tick size)

Trailing Stop (Long) = Current Price - (ATR × 1.5)
Trailing Stop (Short) = Current Price + (ATR × 1.5)
```

### Take Profit Prices

```
TP1 (Long) = Entry Price + (ATR × 2.5)
TP1 (Short) = Entry Price - (ATR × 2.5)

TP2 (Long) = Entry Price + (ATR × 4.0)
TP2 (Short) = Entry Price - (ATR × 4.0)

TP3 (Long) = Entry Price + (ATR × 6.0)
TP3 (Short) = Entry Price - (ATR × 6.0)
```

### Example Calculation

Given:
- Entry Price: $2562.00
- ATR (14-period): $25.00

**Long Position:**
| Level | Formula | Price |
|-------|---------|-------|
| Stop Loss | 2562 - (25 × 1.2) | $2532.00 |
| Breakeven | 2562 + 0.20 | $2562.20 |
| TP1 | 2562 + (25 × 2.5) | $2624.50 |
| TP2 | 2562 + (25 × 4.0) | $2662.00 |
| TP3 | 2562 + (25 × 6.0) | $2712.00 |

## Alert Frequency

### Expected Daily Alert Volume

| Scenario | Entry Alerts | Exit Alerts | Stop Updates | Total |
|----------|--------------|-------------|--------------|-------|
| Low Activity | 2-3 | 4-6 | 2-4 | 8-13 |
| Normal | 4-5 | 8-12 | 4-8 | 16-25 |
| High Activity | 5-6 | 12-15 | 6-10 | 23-31 |

### Alert Timing

- Alerts fire on bar close only (not intrabar)
- Frequency: `alert.freq_once_per_bar`
- No duplicate alerts within same bar
- Stop updates may fire multiple bars in sequence during trending moves

## TradersPost Field Mapping

### Required Fields

TradersPost requires these fields for order execution:

| TradersPost Field | JSON Field | Notes |
|-------------------|------------|-------|
| Symbol | `ticker` | Mapped in strategy settings |
| Side | `action` | "buy" or "sell" |
| Order Type | `orderType` | "market" or "limit" |
| Quantity | `quantity` | Contracts or percentage |
| Limit Price | `limitPrice` | Required for limit orders |
| Stop Price | `stopLoss.stopPrice` | For bracket orders |

### Optional Fields

| TradersPost Field | JSON Field | Notes |
|-------------------|------------|-------|
| Take Profit | `takeProfit.limitPrice` | For bracket orders |
| Sentiment | `sentiment` | For signal tracking |
| Comment | `reason` | For trade logging |

## Error Handling

### Common JSON Errors

**Problem**: Invalid JSON format
```
Error: Unexpected token at position X
```
**Solution**: Verify no special characters in ticker symbol

**Problem**: Missing required field
```
Error: Field 'action' is required
```
**Solution**: Check indicator code generates all required fields

**Problem**: Invalid number format
```
Error: Cannot parse 'NaN' as number
```
**Solution**: Ensure ATR is calculated before alert fires

### Validation Checklist

Before deploying, verify:
- [ ] All prices are valid numbers (not NaN)
- [ ] Quantity is positive
- [ ] Action is "buy" or "sell"
- [ ] Order type matches required fields (limit needs limitPrice)
- [ ] Ticker symbol matches TradersPost mapping

## Testing Alerts

### Manual Test Method

1. Lower minimum confluence to 5/10 temporarily
2. Wait for signal to fire
3. Check TradersPost Activity Log
4. Verify JSON format is correct
5. Restore minimum confluence to 7/10

### JSON Validation Tool

Use online JSON validators to check format:
- [jsonlint.com](https://jsonlint.com)
- [jsonformatter.org](https://jsonformatter.org)

Copy the alert message from TradersPost Activity Log and paste to validate.

### Expected Alert Sequence

For a complete winning long trade:

```
1. ENTRY: {"action": "buy", "quantity": 1, ...}
2. UPDATE: {"action": "update_stop", "reason": "breakeven", ...}
3. TP1: {"action": "sell", "quantity": 0.7, "reason": "TP1_70_percent", ...}
4. UPDATE: {"action": "update_stop", "reason": "trailing", ...}
5. TP2: {"action": "sell", "quantity": 0.25, "reason": "TP2_25_percent", ...}
6. TP3: {"action": "sell", "quantity": 0.05, "reason": "TP3_final", ...}
```

For a losing trade (stopped out):

```
1. ENTRY: {"action": "buy", "quantity": 1, ...}
2. STOP: {"action": "sell", "quantity": 1.0, "reason": "initial_stop", ...}
```

## Customization

### Changing Ticker Symbol

In the indicator settings:
```
Ticker Symbol for Alerts: MGC1!
```

Change to match your broker's symbol format:
- Tradovate: `MGC1!` or `MGCH5`
- TopstepX: `MGC1!`
- Other: Check broker documentation

### Adjusting Quantity Format

The indicator sends quantity as a number. If your broker needs percentage:

Current: `"quantity": 0.7`

For percentage-based exits, TradersPost handles conversion in strategy settings.

### Adding Custom Fields

To add custom fields, modify the alert message construction in Pine Script:

```pinescript
entryAlert = '{"ticker": "' + tickerSymbol + '", "action": "buy", "customField": "value", ...}'
```

## Debugging

### Enable TradingView Logs

1. Open Pine Script console
2. Add `log.info()` statements for debugging
3. Check console for output values

### TradersPost Activity Log

1. Go to Activity tab in TradersPost
2. Filter by strategy
3. Click on individual webhooks
4. View raw JSON payload
5. Check "Response" for broker feedback

### Common Issues

| Symptom | Cause | Fix |
|---------|-------|-----|
| No alerts | Confluence < 7 | Wait or lower threshold |
| Wrong quantity | Fixed contracts setting | Adjust in indicator |
| Missing stop | Price = NaN | Check ATR calculation |
| No execution | Symbol mismatch | Fix mapping in TradersPost |
| Partial fill | Quantity as decimal | Use integer for futures |
